# Как мы работаем с кодом в KREO Studio

Эти правила действуют по умолчанию во всех репозиториях `kreo-it-studio`. Локальный `CONTRIBUTING.md` или `AGENTS.md` проекта имеет приоритет.

## Ветки

- `main` — стабильная ветка, защищена от force-push и удаления.
- Рабочие ветки: `feat/<кратко>`, `fix/<кратко>`, `chore/<кратко>`, `docs/<кратко>`.
- Ветку удаляем после слияния.

## Коммиты

Формат Conventional Commits, текст на русском или английском, одна мысль на коммит:

```
feat(auth): вход по коду из SMS
fix(ios): не падает при пустом ответе API
chore: обновлены зависимости
```

## Pull Request

- Заголовок в том же формате, что и коммит.
- В описании: что изменено, зачем, как проверено.
- Перед запросом ревью: линтер и тесты проходят, секретов в diff нет.

## Секреты

- Никаких `.env`, ключей, токенов и дампов в Git. Шаблон окружения хранится в `.env.example`.
- Секреты CI живут в GitHub Actions Secrets репозитория.

## Именование репозиториев

- `kebab-case`, английский: `<продукт>` или `<продукт>-<часть>`.
- Устаревшие версии: суффикс `-legacy` и статус Archived.
- Topics описывают продукт, стек, платформу и статус (`status-active`, `status-mvp`, `status-paused`, `status-legacy`).
